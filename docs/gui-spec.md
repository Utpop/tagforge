# TagForge GUI 设计规格

> **本文用途**：作为界面设计的输入文档。它不描述代码实现（见 `architecture.md`），
> 只回答"界面要有什么、为什么这样组织、每个控件在什么状态下表现如何"。
> **读者**：UI/UX 设计、前端实现、评审人。
> **版本**：v0.1，对应当前已实现能力（18 项功能 / 9 个接口 / 13 个字段）。

---

## 0. 一句话定位

一个本地单用户的**批量标签工作台**：主界面是一张可直接编辑的表格，
右侧是选中文件的详情，顶部是批量命令条，模板类操作走"参数 + 预览 + 执行"三段式弹窗。

---

## 1. 设计目标（从实现约束倒推，不是审美偏好）

| # | 目标 | 为什么必须 |
|---|---|---|
| G1 | **同列连续修改优先于单文件精修** | 核心场景是"20 个文件改同一列"，表单式往返会放大 20 倍操作成本 |
| G2 | **写盘是显式动作，且代价可见** | 保存有快照成本、可能部分失败，逐键落盘既慢又不可撤销 |
| G3 | **批量上下文必须始终可见** | 用户必须随时知道"我这批操作会作用到哪几个文件" |
| G4 | **危险操作先预览后执行** | 模板写错会污染整批标签，预览是唯一低成本纠错点 |
| G5 | **失败要具体到文件** | 后端返回的是 `failed[]` 列表而非异常，"部分成功"是常态 |

对应三条**设计禁区**：

- 不要做"逐键自动保存"（违反 G2）。
- 不要把批量编辑塞进弹窗或二级菜单（违反 G3，用户会失去作用域感知）。
- 不要用单一"成功/失败"二元提示（违反 G5，抹掉了部分成功状态）。

---

## 2. 能力边界（界面必须承载 vs 明确不做）

**必须进入界面**（否则功能等于不存在）：
扫描目录、列表浏览与排序过滤、单元格编辑、单文件详情、封面查看、批量字段写入、
批量封面写入/移除、覆盖/补空模式选择、文件名反解预览、重命名预览、保存、撤销、
脏值计数、选中计数、异常文件呈现。

**不在本版界面出现**（后端已有能力但无入口，或需要新设计）：
多值字段分离编辑、ID3 版本转换、正则批量替换、动作组、CSV 导出、进度条与取消、
只读模式、播放试听、在线元数据匹配。

> 这些不是"漏了"，是**刻意留白**。界面不要为它们预留空按钮或灰掉的菜单项，
> 那会稀释主流程的清晰度。扩展位见 §12。

## 3. 信息架构

```
主界面 (Single Page)
├─ A 命令区（常驻，顶部）
│   ├─ 目录输入 + 扫描 + 递归开关
│   ├─ 过滤搜索
│   └─ 全局动作：从文件名生成 / 重命名 / 撤销 / 保存
├─ B 批量操作条（常驻，A 下方）
│   ├─ 字段输入：专辑 / 专辑艺术家 / 年份 / 流派
│   ├─ 封面：选择图片 / 移除
│   ├─ 模式：覆盖 / 仅补空
│   └─ 应用到选中
├─ C 主表格（常驻，主区左侧，占宽）
├─ D 详情面板（常驻，主区右侧，定宽）
└─ 浮层
    ├─ E1 从文件名生成（模态，含预览表）
    ├─ E2 按标签重命名（模态，含预览表）
    ├─ E3 确认对话框（撤销 / 移除封面）
    └─ E4 Toast（结果反馈）
```

层级只有两层：**常驻区 4 个 + 浮层 4 类**。不再增加第三层（例如详情面板里再开 tab），
因为所有字段都必须一览无余——这是 G1 的前提。

## 5. 区域规格

### A. 命令区

| 属性 | 规格 |
|---|---|
| 常驻高度 | 44–48px，单行 |
| 元素顺序 | Logo/计数字段 → 目录输入 → 扫描 → 递归开关 → 搜索 → 生成 → 改名 → 撤销 → 保存 |
| 数据依赖 | `state.root`、`state.records.length`、`state.staged` 的字段总数 |
| 副标题 | `{count} 个文件 · {root}`，超长省略，`title` 显示全路径 |
| 保存按钮 | 主色，文案 `保存修改`，右侧徽标显示**脏字段总数**（不是文件数）；为 0 时禁用 |
| 撤销按钮 | 次要样式；无备份时禁用（可选：有 staged 时点击给出冲突提示，见 §9.4） |
| 键盘 | `Enter` 在目录框内触发扫描；`Ctrl/Cmd+S` 触发保存 |

**状态**

- 扫描中：扫描按钮 loading，禁用重复点击；表格保持旧数据不闪空。
- 扫描完成无文件：表格区显示空态文案「该目录下没有可识别的音频文件」。
- 截断：toast 提示「文件过多，已截断显示」。

### B. 批量操作条

| 属性 | 规格 |
|---|---|
| 常驻高度 | 56–64px（含标题行） |
| 标题行 | `批量编辑` + 右侧 `已选 N 个文件` / `未选中（批量操作将无目标）` |
| 字段输入 | 专辑、专辑艺术家、年份、流派（**留空 = 不改动**，占位符写明这一点） |
| 封面 | `选择图片…` 上传本地图；`移除` 清空选中文件封面 |
| 模式 | 单选：`覆盖` / `仅补空`。默认覆盖，必须常显，不可折叠进下拉 |
| 应用按钮 | 无选中时禁用；有选中但四个字段全空且未选封面时，点击提示「没有要写入的内容」 |

**关键约束**：输入框的"空"必须与"未填"在视觉上无差别（都表现为占位符），
因为后端语义就是"空 = 不动"。**不要**提供"清空该字段"的开关放在这里——
删除字段是低频破坏性动作，应放到详情面板的字段级操作里（V1 暂不提供）。

### C. 主表格

| 属性 | 规格 |
|---|---|
| 列（10） | ☐ / 文件 / 标题 / 艺术家 / 专辑 / 专辑艺术家 / 年份 / 音轨 / 碟号 / 流派 / 封面 |
| 列宽 | 文件 300px 定宽，封面 46px，数值列 62px，其余弹性均分 |
| 行高 | 29px（紧凑密度）；可选舒适密度 34px |
| 文件列 | `目录/文件名`，目录段用弱化色；整列 `title` 显示绝对路径 |
| 编辑 | 单元格 `contenteditable`，**单击即进入**，无需双击 |
| 脏值 | 文字变琥珀色 + 该行"有未保存修改"的隐含状态；不要用背景色块（会与选中态冲突） |
| 选中行 | 蓝色低饱和背景（当前文件），与勾选态是两个不同概念 |
| 异常行 | 整行淡红底 + 悬停显示错误原因（解析失败的文件不能静默消失） |
| 排序 | 点击表头切换升降，当前排序列文字高亮 + 箭头 |
| 空态 | 居中「选择一个目录后点击扫描」/「没有匹配的文件」 |
| 全选 | 表头复选框作用于**当前可见（已过滤）**行，不是全部 |

### D. 详情面板

| 属性 | 规格 |
|---|---|
| 宽度 | 320px 固定（不含滚动条） |
| 头部 | 文件名（省略）+ 右侧引擎标签（ID3 / VORBIS / MP4 / APEV2） |
| 封面区 | 最大 210px 高，等比缩放，圆角 6px；无封面时虚线框 + 「无封面」 |
| 字段区 | 12 个字段：标题、艺术家、专辑、专辑艺术家、年份、音轨号、音轨总数、碟号、碟号总数、流派、作曲、备注（备注用多行） |
| 技术信息 | 相对路径 / 文件大小 / 时长 · 码率 / 采样率 · 声道，等宽字体、弱化色 |
| 双向同步 | 面板改字段 → 表格对应单元格同步变脏；表格改完 → 面板同步刷新 |
| 无选中 | 展示「未选择文件」，字段区留空，不要显示可编辑的空表单 |

> 详情面板与表格共用同一份 staged 差量，因此**不允许**出现"表格显示 A、面板显示 B"的情况。
> 设计上要保证两者是同一状态的两种投影。

### E1 / E2. 预览型模态

| 属性 | 规格 |
|---|---|
| 尺寸 | 宽 `min(1080px, 94vw)`，高 `max 86vh`，内部滚动 |
| 骨架 | 标题栏（含关闭）→ 参数行 → 提示行 → 操作行（含统计）→ 预览表 → 底部留白 |
| 预览表 | 左固定（文件名、解析文本）、中间动态列（随模板占位符变化）、右固定（将写入 N 个字段） |
| 单元格语义 | 解析出的值=琥珀色可写；解析失败/缺失=红色 `—`；无变化=灰色「无变化」 |
| 两段式 | 「写入」按钮在预览前禁用；预览后若 `matched=0` 仍禁用 |
| 冲突行 | 重命名弹窗中目标已存在/撞名为红色，且不计入可执行数量 |

### E3 / E4. 确认与反馈

- 确认对话框用于**破坏性**动作：撤销整批、批量移除封面。必须写明作用文件数。
- Toast 只用于**结果**反馈，3 秒自动消失；错误态停留 6 秒。
- 部分失败时 toast 必须写清比例与首个错误原因，例如
  「已写入 7 个，失败 1 个：文件被占用」。禁止只说「部分失败」。

## 6. 状态模型（设计必须理解的三个变量）

```
record.fields   磁盘现状（只读）
staged          未提交意图 Map<path, {field: value}>
checks          勾选集合（批量作用域）
active          当前文件（详情面板主体）
```

派生规则：

| 派生量 | 定义 | 用在 |
|---|---|---|
| 单元格是否脏 | 该文件在 staged 中存在该字段，且值 ≠ `record.fields[field]` | 表格文字色 |
| 保存徽标数值 | staged 中所有字段总数（含跨文件累加） | A 区保存按钮 |
| 保存按钮可用 | 字段总数 > 0 | A 区 |
| 应用按钮可用 | `checks.size > 0` | B 区 |
| 批量作用域 | 有勾选→勾选集；无勾选但点了单文件动作→当前行 | B 区文案、E1/E2 的目标集 |

**两个必须被设计出来的不一致态**：

1. `staged` 非空 且 用户点击撤销 → 磁盘历史与内存意图冲突。设计上给二级确认：
   「有 N 处未保存修改，撤销将只回退已写入的部分」。
2. 保存部分失败 → `applied > 0 && failed.length > 0`。设计上要让失败文件在表格里被
   标出来（整行淡红），而不是只靠 toast。

## 7. 核心交互流程

### 7.1 扫描
```
[输入路径或留空用默认] → [扫描]
  → 禁用按钮 + 保留旧表格（不闪空）
  → 成功：刷新计数字段 + 表格 + 清空 staged/checks/active
  → 空目录：空态文案
  → 出错：toast 错误原因，表格不变
```

### 7.2 单文件编辑（最高频）
```
单击单元格 → 光标进入 → 输入
  → Enter：提交并留在本格
  → Tab / Shift+Tab：提交并跳到下一/上一格（横向遍历本行）
  → Esc：放弃本次输入，回滚为原值
  → 点击别处：提交
提交后：值≠原值 → 置脏并计入徽标；值=原值 → 取消脏
```

### 7.3 批量写入
```
勾选若干行（或全选可见）
  → B 区填写目标字段（只填要改的）
  → 选模式：覆盖 / 仅补空
  → [应用到选中]
  → 即时执行（不走 staged），成功后刷新这些行并清空对应 staged 键
```
> 为什么批量**不**进 staged：批次语义是"一次性动作"，用户预期是立即生效；
> 而单元格编辑是"逐格累积"，需要显式保存。两者混在一起会让"保存"的含义模糊。

### 7.4 从文件名生成（三段式）
```
[生成] → 目标集 = 勾选集 ∪（无勾选时）当前可见集
  → 弹窗：模板预填（依据文件名规律猜测）+ 路径模式开关 + 覆盖开关
  → [预览] → 渲染差异表 + "N / M 可解析"
  → [写入标签] → 成功 toast → 关闭弹窗 → 重新扫描
```

### 7.5 撤销
```
[撤销] → 取最近一条备份 → 确认框（时间 + 涉及文件数 + 标签）
  → 执行 → 重新扫描
```

| 主色 | `--accent` | `#4c9aff` |
| 脏值 | `--dirty` | `#e2b341` |
| 成功 / 危险 | `--ok` / `--danger` | `#3fb96b` / `#e2564c` |

**排版**：正文 13px/1.5；表格 13px；文件列与技术信息用等宽 11.5px；
分区标题 11px 大写 + 字距 0.6px + 弱色。**不要**在表格里用小于 11px 的字。

**间距**：4 的倍数；区域横向内边距 14px；控件间距 7–10px；行内边距 9px。

**圆角**：控件 7px，模态 10px，缩略图 3px，封面大图 6px。

**明暗主题**：V1 只做深色。若要扩展浅色，色板需成对定义，且脏值琥珀在浅色下要加深到
`#8a6212` 级别以保证对比度。

## 11. 边界与极端情况（设计必须给方案）

| 情况 | 设计处理 |
|---|---|
| 字段超长（标题 200 字） | 单元格单行省略 + `title` 全量；详情面板输入框横向滚动 |
| 文件数 2 万+ | 表格虚拟滚动或分页；扫描时保留旧数据 + 顶部细进度条 |
| 单个文件标签解析失败 | 整行淡红 + 该行字段禁用编辑 + 悬停/点击看错误详情 |
| 无封面 | 缩略图列显示 `—`，详情显示虚线空框，不显示破图 |
| 批量操作 0 个目标 | 应用按钮禁用 + 标题行提示「未选中」 |
| 保存部分失败 | toast 报比例 + 首个原因；失败行标红；staged 保留不丢 |
| 撤销时存在未保存修改 | 二级确认，说明只回退已写入部分 |
| 路径超长 | 目录输入框内横向滚动，副标题省略 |

## 12. 扩展位（P1 功能怎么放，不影响现布局）

| 未来功能 | 建议落点 | 对现布局的影响 |
|---|---|---|
| 正则批量替换 / 大小写规范化 | B 区右侧新增「更多动作」下拉，进独立模态 | 无（B 区弹性空间足够） |
| 动作组（可复用流水线） | A 区新增「动作」按钮，侧滑面板 | 无 |
| ID3 版本转换 | 详情面板技术信息区加一行「ID3v2.3 → 2.4」链接 | 无 |
| 多值艺术家编辑 | 详情面板字段支持"标签化输入"（chip） | 该字段行高增加 |
| 批量进度与取消 | 表格顶部替换 toast 为进度条 | 无 |
| CSV 导出 | A 区「更多」菜单 | 无 |
| 只读模式 | 保存按钮旁一个锁形开关，禁用所有可编辑单元格 | 无 |

**设计原则**：新增能力优先占用 A 区的"更多"和 B 区的弹性空间，
不要往主表格加列（每加一列都会挤压已有的字段列）。
